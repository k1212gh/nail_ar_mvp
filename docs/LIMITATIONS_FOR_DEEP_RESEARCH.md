# NailAR 프로젝트 — 한계점 총정리 (딥리서치 입력용)

작성: 2026-07-03. 목적: RayNeo X3 Pro에서 "실제 손톱 위 시스루 AR 격자/디자인 정합" PoC의
막힌 지점 전수 목록. 각 항목에 [증거]와 [리서치 질문]을 달았다.

## A. 광학/디스플레이 물리 (하드웨어 근본 한계)

**A1. 고정 초점면 ~4m vs 손 거리 25–40cm → VAC(수렴-조절 충돌) ~3D.**
편안 한계(±0.25~0.5D)의 ~6–10배. 손에 초점을 맞추면 오버레이가 흐리고, 오버레이에
맞추면 손이 흐림. 소프트웨어로 해결 불가.
[증거] 유저 체감 "존내 흐릿", Cutolo 2020 Frontiers, Kramida TVCG 2016.
[질문] 고정초점 OST에서 근거리 콘텐츠를 "읽을 만하게" 만드는 검증된 완화책 전부?
(단안 렌더, 심볼릭 콘텐츠 제한, 크기/굵기 가이드라인, 초점 가변 애드온 등)

**A2. 아이트래킹 없음 → 근거리 시차 정합오차 ~4.6mm + 눈/머리 움직임에 따른 swim.**
‖E‖ ≈ O′·|p_z/d_focal − 1|, 30cm에서 계수 0.93. 눈 위치 불확실 ±5mm 그대로 투영 오차.
SPAAM류 캘리브는 x/y만 ~0.2–0.5° 개선, 깊이·swim은 불가.
[질문] eye-tracker 없는 OST에서 per-user 정합을 유지하는 최신(2022+) 기법?
(온라인 재캘리브, 헤드포즈 기반 시차 보상, IPD 추정 트릭)

**A3. 디스플레이 = 프레임버퍼 좌/우 분할(왼쪽 절반→왼눈). 시스템 UI는 양쪽 동일(시차 0) = 사실상 2D 모드.**
[증거] 런처 프레임버퍼 분석: 좌우 절반 평균차 1.79 (동일 복사).
[질문] 이런 "2D 복제 우선" 바이노큘러 글래스에서 앱이 의도적으로 눈별 다른 이미지
(시차 제어/단안 렌더)를 넣는 방법? (OpenXR 레이어, per-eye camera, 벤더 API)

**A4. [미해결 핵심 의문] 월드 캔버스 z=2~4m에서도 좌/우 절반 내 콘텐츠 위치가 동일(=시차 0)로 측정됨.**
Unity 헤드카메라 stereoEnabled=false (center-eye 모노 렌더, 런타임이 복제 추정).
그런데 유저는 near 캔버스에서 복시, far(z=100)에서 단일을 경험 — 시차가 0이라면
near/far 차이가 왜 생기나? (도파관 고스트? 실측 시차? 융합 실패?)
[질문] RayNeo X3/OpenXR 어댑터의 스테레오 렌더 경로 실체. 유사 기기(X2)에서
개발자들이 확인한 동작. 모노-복제라면 vergence 제어 불가 → 근거리 응시 시
오버레이 이중시(diplopia)는 구조적 — 맞나?

**A5. 근시 유저 + 4m 가상 이미지 → 도수 보정 없이는 항상 흐림.**
[증거] 유저 안경 착용(거리용 도수 필요), 메모리 기록.
[질문] 프리즘/도수 인서트 없이 근시 유저의 OST 선명도를 높이는 실무 옵션?

## B. 카메라/기하

**B1. RGB 카메라 640×400, 몸체에 ~90° 회전 장착 + 관자놀이 위치(눈과 오프셋).**
피드를 세우려면 회전+미러 8방향 조합을 정확히 맞춰야 하고(오늘 스케일→회전 순서로
축이 꼬여 재빌드 반복), 카메라-눈 시차 때문에 픽셀→디스플레이 매핑이 거리 의존.
[질문] 카메라-디스플레이 정합을 거리별로 파라미터화하는 표준 방법(호모그래피 패밀리,
depth-dependent warp)과 1회 캘리브 UX.

**B2. FOV 불일치 — 카메라 FOV(가로로 넓음, 1.6:1) vs 디스플레이 FOV(좁음) vs 캔버스 1280×480(2.67:1).**
격자/디자인의 각크기·위치 스케일링이 축마다 달라질 위험.
[질문] FOV 매칭 캘리브(각도 기반 매핑)의 실무 레시피.

## C. 검출 파이프라인

**C1. 손톱 "정중앙"이 아니라 랜드마크 외삽 추정치.**
MediaPipe 21 랜드마크의 TIP/DIP에서 기하 외삽 → 실제 손톱판 중심과 계통 오차,
엄지에서 특히 어긋남(유저 보고). 손톱 세그멘테이션 없음.
[질문] (별도 에이전트 조사중) 멀티-손톱 정밀 중심: 공개 데이터셋/모델/제로샷(SAM류).

**C2. 절대거리 추정 정확도 미검증.**
world-landmark 크로스핸드 스팬 + 핀홀(focal_ratio 0.86)로 distM 계산 — 단축은 피했지만
절대 오차(±cm?)를 정량화한 적 없음. 1mm 격자 스케일의 근거가 흔들림.
[질문] 단안 손 거리 추정의 문헌상 오차 범위, 개인 손 크기 보정(1회 스팬 측정) 효과.

**C3. 파이프라인 지연 → 오버레이가 손을 뒤따라옴(swim), 헤드모션 보상 없음.**
글래스 캡처→JPEG→WiFi→PC 추론(~10ms)→응답, 왕복 수십~백ms + 폴링 간격.
캔버스는 head-locked라 머리를 돌리면 격자가 화면에 붙어 따라옴.
[질문] (별도 에이전트 조사중) 예측 필터(OneEuro/Kalman+예측), 헤드포즈 리프로젝션.

**C4. 검출 강건성/UX — 손들고 유지가 힘듦.**
extended/facing 필터로 오검출은 줄었지만, 빠른 락온(1초 내)과 조명/각도 강건성 부족.
[질문] 락온 속도를 올리는 트래킹-우선 설계(detect 1회 → track N프레임) 사례.

## D. 시스템/인프라 (개발 속도를 깎는 것들)

- **D1.** WiFi adb(5555) 수시 offline; USB adb는 Windows 복합 USB 드라이버 문제로 막힘
  (관리자 권한 fix 스크립트 대기 중).
- **D2.** `screencap`이 자주 0바이트/빈 파일 → 원격 검증 루프가 느리고 불안정.
  안경이 능동 렌더 중일 때만 유효 프레임이 잡히는 정황.
- **D3.** Unity MCP 연결이 에디터/윈도 리로드에 취약(현재 끊김) → 자율 빌드 루프 중단됨.
- **D4.** RayNeo SDK 제약: UnityOpenXrActivity 필수, openxr 1.7.0 고정(1.9.1은 SIGSEGV),
  ShareCamera는 XR 세션 필수 → "XR 끄고 순수 2D 앱" 전환이 간단치 않음.

## E. 요구사항 vs 물리의 간극

**E1.** 사장님 신규 PoC = "손톱 중앙 기준 모눈 격자, 시스루 AR, 멀티 손톱" —
A1/A2/A4와 정면 충돌. 가능한 절충: ① 단안(한쪽 눈) 렌더 격자, ② vergence-매칭
동적 깊이(흐림 감수), ③ 원거리 패널+수동 정렬(정합 아님), ④ 매직미러(시스루 아님).
[질문] 각 절충안의 문헌·제품 근거와 기대 정합 정확도(mm/deg), PoC 판정 기준으로
무엇(중심오차 mm, 지터 px, 지연 ms)을 재야 설득력 있는가.

**E2.** 특허 PoC 성공 지표 미정의 — "인식→표시"의 정량 기준(오차/지연/강건성) 합의 필요.
